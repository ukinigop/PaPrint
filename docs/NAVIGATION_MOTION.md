# Customer navigation feedback

The four existing customer tabs remain Print, Shops, Orders and Profile. Selection feedback uses each tab's purpose: a printer rocks and feeds paper (560 ms), a shop lifts while its door opens and closes (520 ms), a receipt tilts and its check pops into place (460 ms), and the profile lifts with a head nod (500 ms). Icons share the app's teal/muted colors, 26-pixel artwork and consistent line weight. This adapts the supplied [BrewedOps animated-icons example](https://brewedops.cloud/motionlibrary/?id=mobile-nav-animated-icons) to PaPrint rather than introducing Alerts or Likes tabs.

Reanimated CSS keyframes animate only transforms and opacity on both the whole icon and its moving part, once per tap. The icon doesn't delay routing. Press feedback is a 0.93 scale over 100 ms; the active tab keeps its soft teal background and readable label. The bar is centered within the existing 438-pixel customer layout and keeps the existing touch-target height. Labels, selected state and safe-area spacing remain available to assistive technology.

The bar now lives alongside the navigation stack, instead of being recreated by each customer screen. It stays mounted while customer routes change and is hidden during uploads, options and review, and on login, admin and shop workspace routes. Shop details keep Shops selected; order details keep Orders selected. Re-selecting the current tab replays only its icon feedback, preserving the current page, search query and scroll position. Polls, bookmarks, profile saves and opening details never increment the selection animation event. Page transitions stay immediate with the stack's animation set to none.

System and account Reduce Motion settings disable icon movement and press scaling. Changing that preference clears previous animation events so enabling motion again cannot replay old animations. New sessions start with static icons. No looping icon animation or haptic dependency was added.

Validation: TypeScript, lint, web export, frontend tests including customer/detail/checkout route classification. Browser checks covered all four distinct finite animations, rapid tab changes, Reduce Motion on and off, stable bar width, details, and checkout hiding/back navigation. Native performance is not yet verified: feel-check a release build on a slower supported Android device, tap tabs quickly, interrupt a switch, and test system Reduce Motion and enlarged text. Expo Go or browser inspection is not a native performance measurement.
